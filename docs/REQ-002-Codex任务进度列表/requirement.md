# REQ-002 Codex 小屏任务卡

## 目标

把 Codex 额度主题中最下方“续期 / 自动”的低价值信息替换为两条“当前 Codex 任务”卡，并增加一个只展示四条 Codex 任务的独立小屏主题。两种展示都直接渲染到灵犀68键盘的 142×428 小屏，不新增桌面软件中的任务列表页，也不改变键盘推送流程。

## 已确认决策

- D-01：任务卡只出现在 `ai-quota` 主题的 Codex 数据源模式；MiMo 等非 Codex 数据源继续显示其自身的紧凑剩余信息，不混入 Codex 任务。
- D-02：保留额度圆环和“下一次重置”卡，重置卡只显示 `ResetsAt` 返回的具体日期时间；移除“订阅 / 每周”“续期 / 自动”以及“偏低 / 留意 / 充足”等派生信息。
- D-03：底部固定显示两条紧凑任务行：优先显示等待确认或运行中的任务；其余只显示已确认完成的任务。无法确认的空闲、中断或仅有更新时间的任务不展示。两条任务都不轮播。
- D-04：任务列表与标题通过本机 `codex app-server --stdio` 读取；为识别另一个 Codex 桌面进程里的状态与计划进度，额外检查对应本地 rollout 文件的最后写入时间、`task_started` / `task_complete` 事件类型，并只统计 `update_plan` 中各计划项的状态数量，不保留或显示步骤文字、消息正文、代码、命令输出、完整提示词或文件路径。应用不会读取、复制或导出 `auth.json`、登录令牌或系统凭据。
- D-05：只有 Codex 实际提供计划步骤时，才显示 `2/4` 等真实进度；没有计划时，已完成任务显示真实完成时间，运行中任务显示最近更新时间，不伪造百分比或完成时刻。
- D-06：小屏主题不提供启动、暂停、打断、归档、删除或发送消息等任务控制能力，只作被动显示。
- D-07：新增独立主题 `codex-tasks`，固定展示四行任务；第一行优先显示等待确认或运行中的任务，其余只显示已确认完成的任务。任务不足四条时显示“暂无 Codex 任务”占位行，不虚构任务。
- D-08：独立任务主题直接读取本机已登录 Codex 的只读任务数据，不依赖额度页当前选择的是 Codex 还是 MiMo；额度主题仍只在 Codex 数据源模式显示任务卡。

## 用户可见结果

1. Codex 额度主题自上而下展示：平台与额度类型、可用额度圆环、下一次重置具体时间、两条最新任务；不显示底部来源说明。
2. 第一条任务优先显示“运行中”或“需要确认”状态、单行任务标题和真实步骤 `n/m`；没有步骤时，完成任务显示完成时间，运行中任务显示更新时间。
3. 最新回合或本地 rollout 事件确认完成时标记“完成了”；界面不显示“最近更新”。
4. 空闲、中断或无法确认状态的任务不展示；不足两条时以“暂无 Codex 任务”补位。
5. Codex 未安装、未登录或 App Server 读取失败时，额度仍可独立显示；任务区域只显示真实的不可用状态。
6. 新的“Codex 任务”主题以四条等高卡片展示任务状态、单行标题与真实步骤/完成时间，第一条始终优先呈现最需要关注的任务。

## 验收证据

- 在 142×428 标准设备帧中渲染：运行中且有计划、运行中但无计划、完成了、需要确认、空闲过滤、读取失败和超长任务标题。
- 在 142×428 标准设备帧中渲染独立任务主题的四条任务、空任务与读取失败状态；标题、右侧进度/时间和状态标签均不越出 `SafeBounds`。
- 断言两条任务标题、重置具体时间和圆环均不超出 `SafeBounds`，JPEG 仍满足 512KB 限制。
- 集成测试只允许 `initialize`、`initialized`、`thread/list`、`thread/read`、`thread/turns/list` 读取请求；不得发送任何任务控制 JSON-RPC 方法。
- 人工检查 [小屏设计稿](design-mock.svg)：不再出现“订阅 / 每周”“续期 / 自动”或底部来源说明，两条任务文字可读且不挤压额度圆环。

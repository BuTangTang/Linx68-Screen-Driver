# 灵犀68屏幕驱动 UI 重设计 V1

状态：设计提案，尚未进入 WPF/XAML 实施。

## 设计稿

- [显示方案](ui-redesign-v1-display-schemes.png)
- [数据服务](ui-redesign-v1-data-services.png)
- [自动化](ui-redesign-v1-automation.png)

设计稿画布为 1586×992，用于表达信息层级；正式实现继续支持当前 1280×800 默认窗口和 1080×680 最小窗口。

## 设计目标

1. 删除“一级侧栏 + 页面内第二套左侧导航”的重复结构。
2. 减少中央空白，让方案选择、状态和关键操作处于同一视线范围。
3. 将右侧预览升级为设备控制台，集中展示在线状态、更新时间、推送和刷新。
4. 新增“数据服务”一级页面，统一解释 Codex、网易云、天气定位和设备连接的来源、新鲜度与错误状态。
5. 保持加载、成功、空数据、陈旧数据和错误状态的卡片几何位置不变。
6. 仅使用可由 WPF `Grid`、`Border`、`ItemsControl`、`RadioButton`、`ProgressBar` 和现有自绘预览实现的视觉结构。

## 页面信息架构

| 一级页面 | 主要内容 | 关键操作 |
| --- | --- | --- |
| 显示方案 | 顶部分类标签、两列方案卡、设备预览控制台 | 刷新数据、立即推送、刷新预览 |
| 数据服务 | Codex、网易云、天气定位、设备连接及刷新活动 | 刷新全部、重新检测、重新定位 |
| 自动化 | 定时推送、音乐场景切换、窗口行为、运行记录 | 立即执行、暂停自动化、测试规则 |
| 外观 | 应用明暗模式、设备屏日夜模式、强调色、字体 | 恢复默认、选择颜色、打开字体文件夹 |
| 其他设置 | 设备地址、启动、托盘及维护设置 | 保存或即时应用 |
| 关于 | 版本、许可、隐私与项目来源 | 打开链接、查看许可 |

## 全局布局

- 标题栏：56 px，保留自定义最小化、最大化和关闭按钮。
- 一级侧栏：设计宽度 210 px；最小窗口可收敛到 188–196 px。
- 主内容外边距：24 px；区域间距：16–20 px。
- 右侧预览或状态栏：设计宽度 330 px；最小窗口下可收敛到 288 px。
- 主内容使用一层滚动容器；固定预览栏独立于主内容纵向滚动。
- 页面标题区高度约 68 px，标题、说明、全局状态和主要动作保持对齐。

### 尺寸

- 基础间距：8 px；常用组合为 8、12、16、24 px。
- 主卡片圆角：12 px；输入框和按钮圆角：8–10 px；状态胶囊使用全圆角。
- 卡片边框：1 px；选中卡片使用 2 px 强调色边框。
- 主要按钮高度：44 px；紧凑按钮：36–40 px。
- 页面标题：26–28 px；卡片标题：16–18 px；正文：13–14 px；辅助信息：11–12 px。
- 正文字体优先 `Segoe UI Variable Text`、`Segoe UI`、`Microsoft YaHei UI`。

## 核心组件

### 一级导航项

- 图标、文字、选中竖条保持同一模板。
- 选中状态使用浅珊瑚底和珊瑚色文字；未选中状态不显示卡片边框。
- 在线设备卡固定在侧栏底部，不随页面内容滚动。

### 分类标签

- 显示方案分类改为标题下的横向标签，不再占用第二列侧栏。
- 标签同时显示名称和数量，例如“Codex 信息 2”。
- 小窗口允许横向换行，不改为下拉框。

### 方案卡

- 默认两列；窄窗口降为一列。
- 设备帧缩略图固定比例，标题和说明位于右侧。
- 选中态使用 2 px 强调边框、浅强调底和右上角勾选标记。
- 卡片高度在加载预览图前后保持不变。

### 设备控制台

- 固定包含：在线状态、设备帧、同步状态、立即推送、刷新预览和当前方案摘要。
- 刷新时保留上一张有效帧，并显示“正在更新预览”，禁止清空或改变容器尺寸。
- 推送成功、失败和重试只改变状态区域，不移动按钮和预览。

### 数据状态卡

- 每项数据必须显示来源、状态、更新时间或耗时。
- `Loading`：保留旧值并显示小型进度指示；首次无旧值时使用等高骨架。
- `Ready`：显示当前值与成功时间。
- `Stale`：保留旧值并明确显示“上次数据”。
- `Empty`：说明缺少数据的原因和可执行动作。
- `Error`：显示简短错误和重试入口，不改变卡片高度。

## 页面实施映射

| 设计区域 | 现有实现或建议承载位置 |
| --- | --- |
| 标题栏、侧栏 | `MainWindow.xaml`、`DesignSystem.xaml` |
| 页面导航状态 | `ShellViewModel` |
| 显示方案标签和卡片 | `ScreenViewModel`、`ThemeGalleryCard` |
| 设备控制台 | `DevicePreviewControl` 与现有推送事件 |
| 数据服务 | 新增页面 ViewModel，复用现有 Codex、音乐、天气与设备状态 |
| 自动化 | `AutomationViewModel` 与定时器状态投影 |
| 外观 | `AppearanceViewModel` 与 Palette 动态资源 |

若新增“数据服务”ViewModel，原因是它聚合多个既有数据源的只读状态，不应继续塞入主题选择页或外观页；不得在该页面复制数据读取逻辑。

## 实施顺序

1. 先抽取全局布局、颜色、间距和通用卡片样式。
2. 实现侧栏与页面框架，保持现有导航功能可用。
3. 实现显示方案页和设备控制台，先解决主流程。
4. 实现数据服务页，只绑定现有数据状态，不改数据源行为。
5. 实现自动化和外观页。
6. 补齐其他设置与关于页的一致性。
7. 最后处理最小窗口响应式布局、键盘焦点、主题明暗和 UI smoke。

## 验收边界

- 设计确认前不开始整体 XAML 重排。
- 实施后必须在 1280×800 和 1080×680 下检查所有页面。
- 浅色、深色和系统模式均要检查，设备屏日间/夜间设置不能与应用主题混淆。
- 快速切换页面、主题和刷新状态时，不允许旧数据覆盖当前页面。
- UI smoke 必须同步更新并全部通过；不能保留失效的主题数量或旧布局断言。

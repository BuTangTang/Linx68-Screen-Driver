# REQ-004 桌面界面与实时体验重构设计

## 信息架构

桌面外壳只保留一层一级侧栏。显示方案页由顶部标题和分类标签、中央两列方案卡、右侧固定设备控制台组成；数据服务页统一承载数据源健康信息；自动化和外观页沿用同一套卡片、间距和状态组件。

| 页面 | 主区域 | 固定操作 |
| --- | --- | --- |
| 显示方案 | 横向分类标签、两列方案卡 | 刷新数据、立即推送、刷新预览 |
| 数据服务 | Codex、网易云、天气定位、设备连接状态卡 | 刷新全部、重新检测、重新定位 |
| 自动化 | 定时推送、音乐切换、窗口行为、运行记录 | 立即执行、暂停、测试规则 |
| 外观 | 应用明暗、设备屏日夜、强调色、字体 | 恢复默认、即时应用 |

设计基线以 `docs/design/ui-redesign-v1-*.png` 和 `ui-redesign-v1-spec.md` 为准。实现可因 WPF 和最小窗口约束压缩尺寸，但不能恢复双侧栏或清空加载中的有效预览。

## 数据状态模型

共享状态使用同一语义：

| 状态 | 内容策略 | 可执行动作 |
| --- | --- | --- |
| `Loading` | 有旧值时保留旧值并标记更新中；首次使用等高占位 | 可取消或等待 |
| `Ready` | 显示当前值、来源、成功时间和耗时 | 刷新 |
| `Empty` | 说明缺少数据原因，使用红色提醒但不伪造异常原因 | 配置或检测 |
| `Stale` | 保留上次有效值并明确“上次数据” | 重试 |
| `Error` | 保留可用旧值，显示短错误和重试入口 | 重试 |

数据服务 ViewModel 只投影刷新协调器的共享状态。状态卡必须使用固定最小高度，标签、更新时间和按钮保持固定位置。

页头刷新活动由预览刷新完成状态统一驱动，不只响应按钮事件：

| 刷新状态 | 页头文案 | 数据保留 |
| --- | --- | --- |
| 首次 `Loading` | `正在刷新…` | 无旧值，设备预览显示等高占位 |
| `Ready` | `预览更新 HH:mm:ss · N ms` | 显示本轮最终快照 |
| 数据源 `Empty` | 仍显示本轮成功更新时间 | 空数据原因由对应固定状态卡说明 |
| 有旧值后失败 `Stale` | `上次预览 HH:mm:ss · 刷新失败` | 保留上一张有效预览和成功时间 |
| 首次 `Error` | `刷新失败` | 无有效帧时同时显示预览失败 |
| `Recovery` | 恢复为最新 `预览更新 HH:mm:ss · N ms` | 用新快照替换旧值 |

后台定时刷新已有成功值时不把页头反复切成加载文案，避免 1 秒刷新周期造成闪烁；数据卡继续显示细粒度加载态。“刷新活动”的时间和总耗时只由“刷新全部”更新，自动预览只重算健康汇总，避免单项耗时与总耗时互相矛盾。

设备连接状态以 `DevicePushResult` 为边界：程序启动且尚未推送时为 `Empty`；HTTP 超时、拒绝或非成功状态在尝试后为 `Error`，保存返回消息和耗时；成功推送为 `Ready`。失败后继续保留本地预览，并设置 5 秒自动重试退避；成功恢复会覆盖错误详情和耗时。

四张数据概览卡统一显示标题、状态徽标、摘要、详情、耗时和来源，并保持固定高度。徽标与 3 px 左侧状态条使用同一语义映射：`Ready` 使用绿色成功色，`Empty/Error` 使用红色危险色，`Stale` 使用黄色警告，`Loading` 使用强调色。

主题卡重建分为首次加载与后续刷新：首次加载按当前选中主题定位分类；后续因外观、字体、日夜模式或预览脏标记重建时，先保存 `all` 或当前分类 ID，注册新卡片后恢复该分类。只有原分类不存在或无主题时，才回退到选中主题所属分类。

## 刷新协调

1. 每次刷新生成递增版本和取消令牌；新的手动刷新、主题切换或日夜切换使旧版本失效。
2. 先确定当前有效主题及所需能力，再并行读取系统、音乐、天气、Codex 额度和 Codex 任务等独立数据。
3. Codex 数据通过共享客户端或共享采集周期获得，额度和任务不分别冷启动完整服务。
4. rollout 回退只读取有限尾部并按文件写入时间缓存，不对未变化文件重复全量解析。
5. 所有源完成或超时后构建一个最终快照；只有当前版本可以更新界面和推送设备。
6. 交互切换可立即用“当前主题 + 已知兼容数据”绘制本地预览，但不得直接复用包含旧主题语义的完整帧。

记录刷新总耗时和各源耗时，供数据服务页与调试日志展示。失败源独立降级，不阻止可用数据渲染。

## Codex 稳定布局

`ai-quota` 始终保留额度摘要和任务摘要的固定区域。任务数据未就绪时在相同区域显示状态文案或骨架，不改用尺寸不同的历史大卡。刷新中继续显示上次有效任务；首次无值、无任务和读取失败仅替换区域内容。

快速切换主题时，预览渲染以新主题定义为准；刷新版本校验防止上一主题的异步结果回写。

## 网易云有效播放时钟

为每个媒体会话维护轨道标识、原始位置、采样时刻、有效位置和播放状态：

- 正在播放且原始位置正常前进：以最新原始位置重新校准。
- 正在播放且原始位置连续冻结：以 `Stopwatch` 单调时间推进有效位置，且不超过曲目时长。
- 暂停：固定有效位置。
- 拖动或原始位置发生明显跳变：立即重新校准。
- 标题、艺术家或会话标识变化：清空旧轨道时钟和歌词选择状态。

歌词行仍按有效位置选择；封面和逐字歌词失败时保留现有降级路径。

## 天气定位

自动定位链路为 Windows `Geolocator` → 经纬度 → 城市反向解析。数据服务页显示：

- 当前模式：Windows 自动定位或手动城市；
- 已解析城市和最近定位时间；
- 权限拒绝、系统位置关闭、超时或反向解析失败；
- 自动失败时实际使用的手动回退城市；
- 重新定位与切换手动模式入口。

定位缓存继续降低系统和网络调用频率，但用户点击重新定位时绕过缓存。

手动城市模式不调用 Windows `Geolocator` 或 BigDataCloud；自动定位失败但手动城市天气可用时，状态为 `Stale` 并显示“手动回退”实际来源。Open-Meteo 陈旧缓存回退要求请求 `LocationKey` 与缓存身份一致，新城市失败直接返回不可用，禁止展示其他城市的旧天气。

## 新显示方案

| ID | 名称 | 分类 | 数据与表达 |
| --- | --- | --- | --- |
| `city-briefing` | 城市晨报 | 时间与天气 | 时间、日期、天气、温度、通勤提示式摘要 |
| `day-rhythm` | 今日节奏 | 时间与天气 | 当前时间、今日进度、星期进度和时段提示 |
| `pixel-companion` | 像素管家 | 系统状态 | 像素表情随 CPU/内存/网络状态变化，并显示关键数值 |
| `signal-garden` | 信号花园 | 系统状态 | CPU 花芯、内存叶片和上下行信号水线组成有机信息图 |
| `music-cassette` | 磁带余晖 | 音乐 | 磁带卷轴随播放进度变化，显示歌名、艺人、当前歌词和进度 |

五个方案复用现有 `SystemSnapshot`，不引入新服务。日间和夜间通过现有 `ScreenCanvas` 颜色映射共享结构。

## 测试策略

- Core Smoke：状态矩阵、主题注册与迁移、全部主题双外观渲染、冻结播放位置推进、刷新版本拒绝旧结果、日志尾部读取边界。
- UI Smoke：六个一级导航、横向分类、主题动态数量、固定预览栏、数据状态卡、1280 × 800 和 1080 × 680 几何检查。
- UI Smoke：自动预览刷新会更新页头活动时间；失败保留上次成功时间，后续成功可恢复。
- UI Smoke：设备首次未连接为 `Empty`，推送失败携带错误详情和耗时并进入 `Error`，成功推送恢复到 `Ready`。
- 真实运行：连续切换页面/主题/日夜、连续刷新、网易云播放操作、自动和手动定位切换；保存关键页面截图并检查空白、裁切和跳动。
- 性能记录：至少记录一次缓存命中和一次完整刷新耗时；若未连接真实设备，明确设备端延迟未验证。

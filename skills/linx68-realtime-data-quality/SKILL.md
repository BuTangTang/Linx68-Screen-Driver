# 灵犀68实时数据质量

把“数据能读到”与“用户始终看到稳定、及时、可信的结果”视为同一个交付目标。不要以编译通过或单张预览图正常代替真实状态转换和连续运行验收。

## 强制工作流

1. 先读取相关需求、当前实现、缓存策略和测试；确认工作区状态，保留无关改动。
2. 改代码前列出状态矩阵：`Loading`、`Ready`、`Empty`、`Stale`、`Error`，以及状态间的转换、可见文案、布局和推送行为。
3. 明确数据新鲜度与性能预算；记录冷读取、缓存命中、渲染和设备推送的分段耗时。
4. 为请求设置取消、超时和“最新请求生效”规则；主题切换后禁止旧请求或旧主题快照覆盖新状态。
5. 将独立数据源并行读取；复用长期连接和缓存，禁止高频启动昂贵进程或反复全量扫描历史文件。
6. 先验证桌面预览，再验证生成帧，最后验证真实设备推送和连续运行。
7. 运行完整构建、核心 smoke 和 UI smoke；任一失败都必须报告，不能只运行容易通过的测试。

## 额度和任务状态

### 现象

额度主题在未获取数据和获取成功后出现两套布局，切换时先显示旧内容再跳版。

### 真因

用 `null` 同时表达“尚未读取”和“不需要任务”，并允许新主题使用上一主题的快照抢先渲染，导致布局分支和数据归属不稳定。

### 处理规则

- 为额度与任务使用明确状态，不能依赖 `null` 猜测加载阶段。
- 所有状态保留相同卡片位置、尺寸和信息层级；只改变内容、提示和弱化样式。
- `Loading` 显示稳定骨架或“正在读取”，`Stale` 保留上次有效值并标出更新时间，`Error` 不清空仍可信的旧值。
- 切换主题时立即取消上一主题请求；禁止把上一主题 `SystemSnapshot` 直接用于新主题。
- 仅在新主题拥有匹配的数据快照后推送；避免先推错误帧再推正确帧。

### 自检

- 分别渲染首次进入、缓存命中、成功、空数据、超时、失败、失败后恢复。
- 比较各状态的关键区域坐标，确保没有跳版、重叠和突然增减卡片。
- 快速连续切换主题，确认最终界面和设备帧只来自最后一次选择。

## 刷新与性能

### 现象

数据显示和切换响应慢；刷新期间可能跳过定时 tick 或重复推送。

### 真因

昂贵数据源串行等待、重复启动本地服务、全量扫描历史文件、同一次操作重复刷新或推送，都会扩大端到端延迟。

### 处理规则

- 为缓存命中、冷读取和失败降级分别设预算；未另行约定时，以缓存状态更新约 `200ms` 内可见、冷读取约 `2s` 内完成或明确显示加载进度为目标。
- 额度和任务等独立请求并行执行，并共享一个可复用的 Codex App Server 会话。
- rollout 或日志只读必要尾部或增量区间；保存读取游标，禁止每次从头扫描大文件。
- 合并重复刷新和设备推送；一次用户操作只产生一个最终有效帧。
- 缓存必须区分数据身份、有效期和来源；允许显示上次有效数据，但必须标明陈旧状态。
- 对每段耗时写入可诊断日志，至少包括数据源、缓存命中、渲染和推送。

### 自检

- 测量首次进入、第二次刷新、网络失败、服务未安装和大 rollout 文件场景。
- 在刷新进行中切换主题或数据源，确认旧结果不会落到新页面。
- 连续运行至少 30 分钟，观察内存、进程数量、磁盘读取和推送频率。

## 网易云音乐与歌词同步

### 现象

网易云仍在播放，但当前歌词停在某一句、切歌后更新滞后，或暂停和拖动后不同步。

### 真因

部分网易云版本提供的 Windows 媒体时间轴不会每秒更新。只读取原始 `Position` 而不根据最后更新时间推进，会让歌词选择器持续收到相同位置。媒体会话存在但时间冻结时，也不会自动进入“无媒体会话”的备用时钟。

### 处理规则

- 将网易云作为明确的适配器和验收对象，不把所有播放器行为视为一致。
- 播放中使用媒体时间轴基准加单调时钟增量计算有效位置；暂停时停止，拖动和切歌时重新校准。
- 检测“状态为播放但位置连续不动”，切换到会话级备用时钟；媒体时间恢复后平滑重新同步。
- 歌曲身份优先使用提供方歌曲 ID；没有 ID 时再组合来源、标题、歌手、专辑和时长。
- 仅在歌曲身份变化时重新匹配元数据和歌词；播放位置刷新不得重复请求歌词网络接口。
- 处理元数据延迟、同名歌曲、现场版、翻唱、无时长和网易云限流，不把错误匹配长时间缓存为成功。

### 自检

- 实测播放、暂停、恢复、拖动、上一首、下一首、单曲循环、锁屏和播放器重启。
- 模拟媒体位置冻结但状态仍为播放，确认歌词继续切换且恢复后不会倒退。
- 连续播放至少 30 分钟，记录歌曲身份、原始位置、有效位置、当前歌词时间戳和切换次数。

## 天气与定位

### 现象

用户无法判断天气来自 IP、Windows 定位还是手动城市，也不知道自动定位失败后使用了哪个位置。

### 真因

定位能力存在，但入口、权限状态、解析结果和回退路径没有形成清晰的用户反馈。

### 处理规则

- 默认说明自动定位使用 Windows 位置服务，不称为 IP 定位。
- 提供“自动定位”和“手动城市”两个明确模式；显示已解析城市、更新时间和“重新定位”操作。
- 权限关闭、超时或反向解析失败时说明原因，并明确显示正在使用的手动城市。
- 禁止静默回退到默认城市；首次使用和回退时让用户看见实际位置来源。
- 不默认增加 IP 定位。若以后需要，只能作为用户主动启用的备用方式，并说明 VPN、运营商出口和隐私误差。
- 缓存坐标和城市名时保留来源与时间；手动切换城市必须立即失效自动位置缓存。

### 自检

- 覆盖定位允许、拒绝、系统服务关闭、超时、反向解析失败、手动城市和自动恢复。
- 验证页面、小屏帧和状态文案展示的是同一个城市及同一种来源。

## 完成标准

交付前必须同时满足：

- 需求中包含状态矩阵、性能预算、回退策略和隐私边界。
- `dotnet build Linx68.ScreenDriver.sln --configuration Debug` 通过且无新增警告。
- 核心 smoke 与 UI smoke 全部通过；更新主题数量或布局时同步维护断言。
- 加载、成功、空、陈旧、失败和恢复均有测试或可重复证据。
- 网易云和天气定位至少完成一次真实环境验证；无法验证时明确标记未验证，不能声称完成。
- 生成的 142×428 JPEG 不越界且不超过设备大小限制；开启自动推送时验证真实设备最终帧。
- 未经用户当轮明确要求，不执行 `git commit` 或 `git push`。
